## 一、供应链基础框架

### 1.1 SCOR 模型（Supply Chain Operations Reference）
供应链五大核心流程：

| 流程 | 英文 | 核心活动 | 关键指标 |
|------|------|----------|----------|
| **计划** | Plan | 需求预测、库存计划、产能规划 | 预测准确率、计划达成率 |
| **采购** | Source | 供应商管理、采购执行、对账结算 | 采购周期、供应商准时交付率 |
| **生产** | Make | 生产调度、质量控制、成本核算 | 生产效率、良品率 |
| **交付** | Deliver | 订单履约、仓储配送、客户服务 | 订单准时交付率、履约成本 |
| **退货** | Return | 逆向物流、售后处理、退款核销 | 退货处理周期、退货率 |

### 1.2 供应链产品类型
- **B2B 供应链产品**：供应商门户、SRM 系统、采购平台
- **B2C 供应链产品**：电商平台、订单系统、履约系统
- **内部工具**：WMS、TMS、ERP 对接、库存管理

## 二、核心系统架构

### 2.1 SRM（Supplier Relationship Management）
**核心模块：**
- 供应商准入/认证/分级管理
- 采购寻源（招标、询价、竞价）
- 采购合同/订单管理
- 供应商绩效评估（QCDS：质量、成本、交付、服务）
- 对账结算/付款管理

**关键流程：**
```
供应商注册 → 资质审核 → 合同签订 → 采购订单 → 发货通知 → 
收货质检 → 入库确认 → 对账结算 → 付款
```

### 2.2 WMS（Warehouse Management System）
**核心模块：**
- 入库管理（收货、质检、上架）
- 库内管理（移库、盘点、调拨）
- 出库管理（拣货、复核、打包、发货）
- 库存管理（安全库存、预警、批次/效期）
- 仓储策略（ABC 分类、波次、先进先出）

**关键指标：**
- 库存周转率 = 年销售成本 / 平均库存
- 库存准确率 = 盘点准确 SKU 数 / 总 SKU 数
- 订单履约率 = 准时交付订单数 / 总订单数
- 拣货效率 = 拣货行数 / 人时

### 2.3 OMS（Order Management System）
**核心能力：**
- 订单接入（多平台、多渠道）
- 订单拆分/合并
- 库存分配（占用、释放）
- 履约路由（多仓发货、就近配送）
- 订单状态追踪
- 逆向订单（退货、换货、退款）

### 2.4 ERP 对接要点
- **主数据同步**：物料、供应商、客户、BOM
- **业务单据**：采购订单、销售订单、出入库单
- **财务对接**：应收应付、成本核算
- **接口方式**：API、中间表、EDI、文件交换

## 三、电商供应链核心场景

### 3.1 商品管理
**SPU/SKU 设计原则：**
- SPU（Standard Product Unit）：标准化产品单元，如"iPhone 15"
- SKU（Stock Keeping Unit）：库存量单位，如"iPhone 15 黑色 128G"

**属性设计：**
```
基础属性：类目、品牌、型号、规格
销售属性：颜色、尺寸、容量
物流属性：重量、体积、包装方式
业务属性：是否预售、是否定制、发货时效
```

### 3.2 库存管理
**库存类型：**
- 可用库存 = 总库存 - 锁定库存 - 预留库存
- 在途库存（已采购未入库）
- 安全库存（应对需求波动）
- 虚拟库存（预售/调拨场景）

**库存分配策略：**
- 先进先出（FIFO）：适合有保质期商品
- 后进先出（LIFO）：适合大宗商品
- 按批次/效期优先
- 按仓库优先级（就近发货）

### 3.3 订单履约
**履约流程：**
```
下单 → 库存预占 → 支付 → 订单审核 → 仓库拣货 → 
打包 → 发货 → 物流追踪 → 签收 → 确认收货
```

**异常处理：**
- 缺货：拆单发货、调拨、采购补货
- 超时未发货：自动取消、补偿
- 物流异常：拦截、改派、重发

### 3.4 逆向物流
**退货类型：**
- 7 天无理由退货
- 质量问题退货
- 发错货/漏发货
- 物流破损

**退货流程：**
```
退货申请 → 审核 → 退货地址 → 寄回 → 仓库质检 → 
入库 → 退款/换货/维修
```

## 六、常见痛点与解决方案

### 6.1 库存不准
**原因：**
- 系统库存与实物不一致
- 多系统数据不同步
- 人为操作失误

**解决方案：**
- 定期盘点 + 循环盘点
- 系统间实时同步（消息队列）
- 操作留痕 + 权限管控

### 6.2 超卖
**原因：**
- 库存扣减时机不当
- 并发下单未做锁库存
- 多渠道库存未隔离

**解决方案：**
- 下单预占 + 支付确认扣减
- 分布式锁/Redis 原子操作
- 渠道库存隔离 + 安全库存

### 6.3 履约效率低
**原因：**
- 拣货路径不合理
- 波次策略不优
- 人工操作占比高

**解决方案：**
- 智能拣货路径规划
- 波次合并（同区域、同 SKU）
- 自动化设备（AGV、分拣线）

## 九、高阶能力：从执行到战略

### 9.1 供应链战略规划
**三步法：**
1. **诊断现状**：绘制当前供应链价值流图（VSM），识别浪费环节
2. **设定目标**：对齐业务战略（成本领先/差异化/快速响应）
3. **设计路径**：分阶段实施（0-6 月/6-18 月/18-36 月）

**战略类型选择：**
| 战略 | 适用场景 | 核心能力 | 代表企业 |
|------|----------|----------|----------|
| **效率型** | 标品、需求稳定 | 规模经济、自动化 | 沃尔玛、Costco |
| **响应型** | 时尚、快消品 | 快速补货、柔性生产 | Zara、SHEIN |
| **定制型** | 高价值、个性化 | C2M、模块化设计 | 戴尔、红领 |
| **风险抵御型** | 关键零部件、地缘风险 | 多源采购、安全库存 | 苹果、华为 |

### 9.2 数字化转型框架
**四层架构：**
```
L4 决策层：AI 预测、智能调度、数字孪生
L3 协同层：SRM/CRM、供应链控制塔、多方协同
L2 执行层：WMS/TMS/OMS、自动化设备
L1 感知层：IoT、RFID、条码、传感器
```

**转型优先级评估矩阵：**
| 维度 | 高优先级 | 中优先级 | 低优先级 |
|------|----------|----------|----------|
| **业务价值** | 直接降本/增收 | 效率提升 | 体验优化 |
| **实施难度** | 3 个月内可上线 | 3-12 月 | 12 月+ |
| **数据基础** | 数据完备 | 部分缺失 | 需从零建设 |

### 9.3 供应链金融产品设计
**核心场景：**
- **应收账款融资**：供应商凭订单/发票提前回款
- **存货融资**：在库商品作为抵押物
- **预付款融资**：采购商预付货款融资
- **信用账期**：基于历史交易的授信额度

**风控要点：**
- 贸易背景真实性验证（三流合一：物流/资金流/信息流）
- 核心企业确权
- 动态监控（库存预警、经营异常）

## 十、头部案例拆解

### 10.1 SHEIN：小单快反模式
**核心逻辑：**
```
小批量测款（100-500 件）→ 实时数据监控 → 
爆款快速返单（7 天上新）→ 滞销款立即下架
```

**关键能力：**
- 供应商深度绑定（广州番禺 300+ 核心工厂）
- 数字化系统直连（工厂端 MES 系统）
- 数据驱动设计（Google Trends + 站内行为）

**可借鉴点：**
- 笨鸟商城配件可尝试"小批量测款 + 快速迭代"
- 建立供应商响应速度评级体系

### 10.2 京东：仓配一体化
**核心逻辑：**
- **211 限时达**：11:00 前下单当日达，23:00 前下单次日 15:00 前达
- **前置仓**：热销 SKU 下沉到城市仓/站点
- **智能补货**：基于销量预测自动调拨

**关键指标：**
- 现货率 > 97%
- 订单履约成本 < 6 元/单
- 库存周转天数 < 30 天

### 10.3 美团优选：社区团购供应链
**核心逻辑：**
```
中心仓 → 网格仓 → 团长（自提点）→ 用户
```

**创新点：**
- **以销定采**：T+1 预售模式，零库存风险
- **集采集配**：降低采购成本 + 物流成本
- **损耗共担**：供应商/平台/团长分摊机制

### 10.4 菜鸟：供应链控制塔
**核心能力：**
- 全链路可视化（从工厂到消费者）
- 异常预警（延迟、缺货、质量）
- 智能决策（路由优化、库存调拨）

**技术架构：**
- 数据中台：统一数据标准 + 实时计算
- 算法中台：预测、优化、调度引擎
- 业务中台：开放 API 供生态伙伴调用

```
L1 执行层（0-2 年）：需求分析、原型设计、项目跟进
```

**核心问题：** 口袋仓账实不符
**解法：**
1. 核销强制关联工单（防止虚假核销）

### 17.3 ERP 与电商系统对接规则

**主数据同步：**
```
物料同步：ERP → 电商系统（物料编码、名称、规格）
供应商同步：ERP → 电商系统（供应商编码、名称、账期）
客户同步：电商系统 → ERP（客户信息、收货地址）
价格同步：ERP → 电商系统（成本价、建议零售价）
```

**业务单据对接：**
```
销售订单：电商系统 → ERP（生成销售订单、触发发货）
采购订单：电商系统 → ERP（生成采购需求）
入库单：WMS → ERP（入库确认、库存更新）
出库单：WMS → ERP（出库确认、成本结转）
退货单：电商系统 → ERP（退货入库、退款处理）
```

**财务对接：**
```
应收单：电商系统 → ERP（确认收入、生成应收）
应付单：电商系统 → ERP（确认成本、生成应付）
收款单：电商系统 → ERP（收款核销）
付款单：电商系统 → ERP（付款核销）
```

### 17.4 对接技术要点

**接口方式选择：**
| 方式 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| API 调用 | 实时性要求高 | 实时同步、灵活 | 开发成本高 |
| 中间表 | 批量同步 | 简单、易维护 | 实时性差 |
| 文件交换 | 大数据量 | 适合离线处理 | 需要定时任务 |
| 消息队列 | 异步解耦 | 高并发、可靠 | 架构复杂 |

**数据一致性保障：**
- **幂等性设计**：同一请求多次执行结果一致
- **事务管理**：分布式事务或最终一致性
- **对账机制**：定期对账、差异告警
- **异常处理**：失败重试、人工介入

### 17.5 笨鸟 ERP 对接现状分析

| 对接项 | 现状 | 问题 | 建议 |
|--------|------|------|------|
| 物料同步 | 部分同步 | 编码规则不统一 | 建立统一物料编码体系 |
| 销售订单 | 手动导入 | 效率低、易出错 | 开发自动对接接口 |
| 库存同步 | 定时同步 | 延迟导致超卖 | 改为实时同步 + 预占机制 |
| 财务对账 | 手工对账 | 耗时、易出错 | 开发自动对账功能 |
| 采购对接 | 未对接 | 采购信息不透明 | 对接 SRM 系统 |
