### 2.3 各工具详细分析

#### 🥇 第一梯队（强烈推荐）

**ChatGPT (GPT-4o)**
- 知识库：支持上传 PDF/Word/Excel/TXT，自动解析
- 对话：上下文理解最强，多轮对话流畅
- 聪明度：逻辑推理、代码生成、创意写作均为顶级
- 费用：免费版 GPT-4o 有使用限制，Plus $20/月
- 适用场景：复杂分析、代码辅助、创意工作

**Claude (Sonnet/Opus)**
- 知识库：支持 200K tokens 上下文，文档理解优秀
- 对话：语气自然，擅长长文档处理
- 聪明度：推理能力接近 GPT-4，代码能力强
- 费用：免费版有限额，Pro $20/月
- 适用场景：长文档分析、合规审查、内容创作

#### 🥈 第二梯队（日常使用）

**DeepSeek**
- 知识库：支持文件上传，解析速度快
- 对话：中文理解好，响应速度快
- 聪明度：代码生成能力强，逻辑推理良好
- 费用：目前免费，未来可能收费
- 适用场景：代码辅助、日常问答、文档处理

**Kimi**
- 知识库：200 万字超长上下文，行业领先
- 对话：中文友好，适合长文档问答
- 聪明度：信息提取能力强，推理中等
- 费用：目前免费
- 适用场景：长报告分析、论文阅读、资料整理

#### 🥉 第三梯队（备选）

**通义千问 / 文心一言 / 智谱清言**
- 优势：国产合规、免费额度大、中文场景优化
- 劣势：复杂推理能力稍弱、国际资料覆盖少
- 适用场景：日常办公、内部文档处理、合规要求场景

### 2.4 本地部署方案参考

#### 方案 A：Ollama（推荐新手）

```bash
# 安装

  "model": "qwen2.5:7b",
```

```
- 用户痛点：[列出 3-5 条]
- 现有流程：[简述]

【输出要求】
1. 用户需求分层（Must have / Nice to have）

【约束条件】

```

```
- 功能名称：[名称]

- 避免模糊描述（如"尽快"、"大概"）
```

### 3.2 AI 生成业务流程图/产品流程图/原型图

#### 方法 1：文字描述 → Mermaid 流程图
```
【Prompt 示例】
请将以下业务流程转换为 Mermaid 流程图代码：

流程：商家退货审批
1. 商家提交退货申请
2. 系统校验订单状态
3. 运营人员审核（通过/驳回）
4. 通过后生成退货地址
5. 商家发货并填写物流单号
6. 仓库收货验货
7. 财务退款

要求：
- 使用 flowchart TD 格式
- 区分不同角色（商家/系统/运营/仓库/财务）
- 标注判断节点
```

**输出示例**：
```mermaid
flowchart TD
    A[商家提交退货申请] --> B{系统校验订单状态}
    B -->|校验通过 | C[运营人员审核]
    B -->|校验失败 | D[驳回并通知商家]
    C -->|通过 | E[生成退货地址]
    C -->|驳回 | D
    E --> F[商家发货并填写物流单号]
    F --> G[仓库收货验货]
    G --> H{验货通过？}
    H -->|是 | I[财务退款]
    H -->|否 | J[异常处理流程]
```

### 3.3 产品 + 技术融合建议

#### 为什么产品需要懂技术？
1. **沟通效率**：能用技术语言与研发对话，减少理解偏差
2. **可行性评估**：初步判断需求实现难度，避免过度承诺
3. **原型即代码**：AI 辅助下，产品可输出可运行的原型
4. **数据思维**：理解数据结构，设计更合理的埋点和接口

#### 产品应掌握的技术知识（优先级排序）
```
P0（必须）：
├── 基础 SQL（SELECT/WHERE/JOIN）
├── API 概念（REST/请求响应/状态码）
├── 数据结构（JSON/数组/对象）
└── 前端基础（HTML/CSS 概念）

P1（建议）：
├── Git 基础（clone/pull/branch）
├── 数据库设计（表/字段/索引）
├── 认证授权（Token/Session）
└── 基础部署概念（环境/域名/SSL）

P2（加分）：
├── Python/JavaScript 基础语法
├── 正则表达式
├── 命令行基础
└── CI/CD 流程理解
```

### 4.3 如何判断 AI 生成的代码是否正确

#### 验证清单
```
□ 1. 语法检查
  - 能否通过编译/解释器检查
  - 有无语法错误警告

□ 2. 逻辑验证
  - 边界条件是否处理（空值/极值/异常）
  - 循环是否有终止条件
  - 异步操作是否正确处理

□ 3. 安全审查
  - SQL 是否使用参数化查询
  - 用户输入是否有校验/转义
  - 权限校验是否到位

□ 4. 性能评估
  - 有无 N+1 查询问题
  - 循环内有无重复计算
  - 大数据量场景是否可行

□ 5. 可维护性
  - 命名是否清晰
  - 函数是否单一职责
  - 有无重复代码

□ 6. 测试覆盖
  - 单元测试是否通过
  - 关键路径是否有测试
  - 边界情况是否覆盖
```

#### 实用技巧
1. **让 AI 自己 Review**：生成代码后，再让 AI 审查一遍
2. **对比多模型输出**：用不同 AI 生成同一功能，对比差异
3. **小步验证**：先运行核心逻辑，再逐步扩展
4. **人工抽查**：关键业务逻辑必须人工 Review
5. **CI 自动化**：将 AI 生成代码纳入 CI 流程自动检测
