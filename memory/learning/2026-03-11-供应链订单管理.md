## 一、退款单设计核心原则

### 1. 单据解耦

```
业务层：销售订单 → 退货订单（货物流）
财务层：退款单 → 结算单（资金流）
```

**为什么解耦？**
- 业务变更不影响财务对账
- 支持部分退款、多次退款场景
- ERP 对接更清晰（业务单据 + 财务单据分别推送）

### 2. 退款单必备字段

| 字段 | 类型 | 说明 |
|------|------|------|
| refund_id | string | 退款单号 |
| order_id | string | 关联销售订单 |
| return_order_id | string | 关联退货订单 |
| refund_type | enum | 仅退款/退货退款 |
| refund_amount | decimal | 退款金额 |
| refund_reason | string | 退款原因 |
| approval_role | enum | 平台/商家 |
| status | enum | 待审批/已审批/已打款/已关闭 |
| items | array | 退款明细（继承退货单商品明细）⚠️ 关键 |

### 3. 结算单生成规则

```
正向结算单 = 销售订单实付金额（+）
逆向结算单 = 退款单实退金额（-）
```

**关键点**：
- 结算单金额必须从退款单获取（不是退货单）
- 结算单需同时关联业务单据（退货单号）和财务单据（退款单号）
- 支持部分退款：退货 10 元 → 退款 5 元 → 结算 -5 元

## 二、审批流设计

| 退款类型 | 审批方 | 原因 |
|----------|--------|------|
| 仅退款 | 平台 | 无货物流，平台承担风险 |
| 退货退款 | 商家 | 商家需确认收货、验货 |

**审批状态机**：
```
待申请 → 待审批 → 已审批 → 执行中 → 已完成
              ↓
            已驳回
```

## 三、竞品参考（京东/淘宝/拼多多）

### 京东模式
- 退款单独立存在，与订单 1:N
- 退款单有完整商品明细
- 自营商品：京东审批；第三方：商家审批

### 淘宝模式
- 退款/退货合一，退款单继承订单快照
- 小二介入机制（纠纷升级）
- 结算单 T+1 生成

### 拼多多模式
- 仅退款门槛低（平台补贴）
- 退款单与优惠券/红包拆分计算
- 商家保证金自动扣款

## 四、笨鸟商城建议

1. ✅ 退款单必须继承退货单的商品明细（解决对账问题）
2. ✅ 商家端展示退货单 + 退款金额（隐藏退款单详情）
3. ✅ ERP 推送双单据：退货单（业务）+ 退款单（财务）
4. ⚠️ 部分退款场景需在退货单标记"已退金额"
5. ⚠️ 商家审批超时需有 SLA（如 48h 自动流转平台）
